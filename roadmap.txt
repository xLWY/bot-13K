xlwy bot - Codebase map (refreshed November 2026)

Goal
- Practical map of the codebase: main folders and responsibilities, not every file.
- This is descriptive, not a promise that every listed system is complete.

Root
- index.js             -> process entry point (imports src/app.js)
- package.json         -> scripts, dependencies, project metadata (v2.0.0, ESM)
- README.md            -> setup and usage documentation
- docs/                -> COMMANDS.md, DEPLOYMENT.md
- SECURITY.md          -> security policy
- scripts/             -> migrate.js, backup.js, restore.js, restore-drill.js
- Dockerfile, docker-compose.yml, railway.json -> container deployment
- .env.example         -> every supported environment variable
- tests/               -> node:test suites (failure paths + pure unit tests)

src/
- app.js               -> Discord client, intents, startup, web server, cron jobs

- commands/            -> 61 JS files across 11 folders
  - root:              -> diag, help, logtest, ping
  - Giveaway/          -> gcreate, gend, gdelete, greroll
  - JoinToCreate/      -> jointocreate + modules/ dashboards
  - Moderation/        -> ban, kick, timeout, warn, clear, roles, mass actions, staff panel...
  - Owner/             -> ownerrole, manage (list/info/leave, DM-capable)
  - Reaction_roles/    -> reactroles
  - ServerStats/       -> serverstats, t + modules/ dashboards
  - Settings/          -> prefix, logs, leveling, panel + modules/ dashboards
  - Ticket/            -> ticket, claim, close + modules/ dashboard
  - Utility/           -> avatar, serverinfo, userinfo, embedbuilder, hoxley, wipedata
  - Welcome/           -> modules/greet_dashboard.js
  NOTE: files under modules/ are not registered as slash commands. The loader skips
  any directory named "modules"; those files implement dashboards opened by a parent command.

- config/              -> application.js, bot.js, postgres.js, schemaVersion.js, shop/
- events/              -> 21 Discord event listeners (ready, interactionCreate,
                          messageCreate/Update/Delete, guildMember*, voiceStateUpdate,
                          role*, channel*, presenceUpdate, moderationGateway, audits)
- handlers/            -> commandLoader.js, events.js, interactions.js,
                          interactionHandlers/, ticketButtons.js
- interactions/        -> buttons/, modals/, selectMenus/ component handlers
- services/            -> 23 business-logic modules (database, guildConfig, ticket,
                          giveawayService, birthdayService, leveling, xpSystem,
                          serverstatsService, reactionRoleService, joinToCreateService, ...)
- utils/               -> 41 shared helpers (logger, embeds, interactionHelper,
                          errorHandler/errorRegistry, sanitization, validation,
                          rateLimiter, abuseProtection, database backends, ...)

Database abstraction layer
- PostgreSQL is the primary store; scripts/migrate.js manages schema versions.
- On connection failure the bot switches to in-memory storage: nothing persists and
  all data is lost on restart. /health reports database.degraded, /ready returns 503.

Command registration notes
- DM_ENABLED_COMMANDS + GLOBAL_COMMANDS live in src/config/commandMeta.js
  (imported by commandLoader.js, help.js and prefixCommands.js).
- Owner-only commands use `ownerOnly: true` plus isBotOwner() in execute().
- Global commands are registered with contexts [0, 1] so /manage stays usable in DMs;
  default_member_permissions is stripped globally and rechecked in code.

Notes
- Architecture: commands -> handlers -> services -> utils.
- bot.js is the single source of truth for embed colors and core feature flags.
- Some systems are still evolving; verify against the source before relying on a name here.
